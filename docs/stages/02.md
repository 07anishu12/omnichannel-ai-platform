### Decision proposal for the operator (no contract-dependent changes made)

1. `DATABASE_URL` vs split `MYSQL_*`. Recommended: keep split `MYSQL_*` as canonical for Stage 02. It is already implemented, tested, and used by compose and `.env.example`. The AI-service guard already forbids both forms, so the credential boundary does not depend on the choice. Alternative: adopt `DATABASE_URL` for api, which needs `config.ts`, tests, `.env.example`, and compose changes.
2. `AI_SERVICE_URL`. Recommended: define as optional for api and worker with default `http://127.0.0.1:8000`. Required only once a later stage adds AI call paths. The AI service must never read it as a database variable.
3. `APP_ORIGIN`. Recommended: define as optional for api with default `http://127.0.0.1:3000`, applied when web or CORS behavior exists.
4. Compose and `.env.example` literals. `deploy/local/compose.yaml` and `.env.example` still hold `local-app-password` and `local-root-password`. These are local placeholders, not real secrets. Options: env-interpolate with a documented default, or keep the literals and document them as local-only.
