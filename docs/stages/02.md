Stage 02 is not accepted yet. In a fresh clone, `pnpm typecheck` failed intermittently at `5ce9476`. Root cause: the workspace packages `@omni/contracts` and `@omni/security` resolve through `package.json` `exports` to `./dist/*.d.ts`, and `dist/` only exists after a build. A fresh clone has no `dist/`, so `tsc` reports TS2307 for both imports. Earlier passes reused build output left in the working copy. Commit `654e7b8` makes `typecheck` build those two packages first, mirroring the existing `test` script. The status stays `null` until the operator-facing gaps listed under "Final status" are closed.

## Credential boundary (Python must not hold MySQL write credentials)

- `services/ai-service/app/config.py` lists `DATABASE_URL`, `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD`, and `MYSQL_ROOT_PASSWORD` as forbidden. `load_settings()` raises when any is set. The earlier check with `DATABASE_URL` set raised `RuntimeError`.
- `services/ai-service/tests/test_app.py` includes a `MYSQL_PASSWORD` guard test.
- `deploy/local/compose.yaml` defines no `ai-service` container. MySQL credentials appear only in the `mysql` service block.

Limit: the AI service is not containerised, so there is no compose-level proof that it receives no MySQL credentials. Its boundary is proven only by the code guard and a process started with those variables unset.
